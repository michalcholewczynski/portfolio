# Developer Portfolio Plan

## Purpose

Build a fast, single-page portfolio for a developer and web creator. The site presents the person, selected web projects, and a direct way to make contact. It should feel like a focused personal workspace with subtle code-editor cues—not a generic SaaS landing page.

## Audience

The primary audience is prospective clients, collaborators, and recruiters who need to understand the developer’s skills and work quickly, especially on mobile devices.

## Scope

The portfolio is written in plain HTML, CSS, and JavaScript, with no framework, build step, backend, or external UI dependency. It includes:

- An **About** section with a short biography and GitHub and LinkedIn links.
- A **Projects** section with three project tiles, each with an honest description, technology labels, a project link, and a lightweight CSS preview until real screenshots are available.
- A **Contact** section with a clear `mailto:` link and social links.
- A compact navigation, responsive layout, basic metadata, and a favicon.

## Design Direction

Use a dark, editor-inspired interface with deliberate typography, restrained color accents, and readable code-like details. The visual treatment must support the portfolio’s content. Avoid invented achievements, filler sections, excessive cards, gradients, decorative effects, and unnecessary animation.

## Content Rules

Personal details, project URLs, screenshots, and descriptions begin as clearly identifiable placeholders and must be replaced with verified information. Calls to action should be explicit, for example “View project” or “Write an email.”

## Definition of Done

The page works without JavaScript, is fully usable from 320 px upward, has visible keyboard focus states, honors reduced-motion preferences, and has no horizontal overflow or console errors. It should present a distinct, credible developer portfolio rather than a reusable template.
